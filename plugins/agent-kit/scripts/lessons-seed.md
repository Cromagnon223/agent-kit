## From past projects (shipped with the kit)
- Gather every constraint up front (offline or online, OS, who runs it, GUI or terminal). Constraints that arrive one at a time cause rebuilds.
- Deliver things the user can double-click. Ship zips rather than bare .bat files, and never ask them to run a terminal command or reinstall.
- Deliver through an auto-updating channel (a GitHub plugin or marketplace) from day one; never make the user download zips again and again or redo a setup step.
- Check work against the user's first request at milestones only (the plan and the final result), not on every step.
- Pick the cheapest model that can do the job; send reading, lookups and tests to Haiku helpers.
- Don't ask clarifying questions. Choose a sensible default, say it in one line, and finish.
